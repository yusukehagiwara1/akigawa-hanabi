## 3. 本番反映の手順

要点: **いきなり本番ページを書き換えず、まず「確認用の下書きページ」に同じ内容を入れて見た目と動きを確かめてから、ページ1711に反映します。** 実作業はこれまでと同じく Claude に依頼できます（このファイルを見せれば手順どおり進められます）。

### 手順0. 手元での事前確認（任意）
- `out\_test_quiz.html` をブラウザで開くと、①②の動きだけを確認できます（サイトのデザインは当たっていないので、見た目は本番と少し違います）。

### 手順1. 現在の本文をバックアップする
- REST API で `GET https://machizukuri-con.or.jp/wp-json/wp/v2/pages/1711?context=edit` を実行し、`content.raw` をファイルに保存します。
- 9月5日に取得した `wp\page_1711_raw.html` を元に新版を作っています。**9月5日以降に管理画面でチケットページを編集していた場合は、新版を作り直す必要があります**（`out\integrate.py` を再実行するだけです）。バックアップと `wp\page_1711_raw.html` が同じ内容かを最初に確認してください。

### 手順2. 権限を確認する（重要）
- 上の GET の応答にある `_links` に `wp:action-unfiltered-html` があることを確認します。これが無いユーザーで保存すると、診断の `<style>` `<script>` が**エラーなしで丸ごと削られ**、診断が動かず見た目も崩れます。無ければ管理者のアカウントで行うか、作業を止めて相談してください（これまで使っている staff3 では script タグの保存ができています）。

### 手順3. 確認用の下書きページを作って確かめる
1. `POST https://machizukuri-con.or.jp/wp-json/wp/v2/pages` で、`status` を `draft`、タイトルを「【確認用】チケット情報（新版）」、`content` を `out\page_1711_new.html` の中身にした下書きページを作ります。公開されないので一般の方には見えません。
2. WordPress 管理画面 → 固定ページ → 下書き → 「プレビュー」で表示します（スマホで見るときは、スマホでも管理画面にログインしてからプレビューを開きます）。
3. 確認すること:
   - 上から「チケットの入手方法は3つ」→「どの席にしようか迷ったら」（診断）→「販売サイト」の順に並んでいる。
   - **iPhone の Safari で**: 横スクロールが出ない。診断の選択肢をタップすると次の質問→結果に切り替わり、画面が飛ばない。結果の写真が表示される。「この席をアソビューで予約する」を押すとアソビューが新しいタブで開く。
   - 席の写真・駐車場の案内図をタップすると拡大され、閉じられる。
   - SS席・S席・A席のカードに「アソビューで予約する」ボタンと「他の販売サイト…で購入する」リンクがある。
   - 下書きをブロックエディタで開いても「ブロックに予期しないコンテンツが含まれています」という警告が出ない。
   - 気になる点があれば、ここで直してから次へ進みます。

### 手順4. 本番（ページ1711）に反映する
- `POST https://machizukuri-con.or.jp/wp-json/wp/v2/pages/1711` で `content` に `out\page_1711_new.html` の中身を送ります。
- 送るときは本文を必ず JSON エンコーダで包みます（Python なら `json.dumps({"content": text}, ensure_ascii=False)`）。文字列を手組みすると 400 エラーや `&` の化けが起こります。
- 更新はアクセスの少ない時間帯に行い、公開後すぐに手順5を行います。

### 手順5. 反映後の確認
- もう一度 `GET …/pages/1711?context=edit` を取得し、`content.raw` が `page_1711_new.html` と完全に一致すること（`<script>` が1回、`<style>` が2回残っていること）。
- 公開ページ https://machizukuri-con.or.jp/ticket/ を iPhone Safari の実機で開き、手順3と同じ項目を確認。トップページの「チケット情報を見る」や「チケットを購入する！」（`/ticket/#site`）が、これまでどおり「販売サイト」の位置に着地すること。
- GA4 の DebugView で `seat_quiz_start` → `seat_quiz_result` → `seat_quiz_cta` が届くこと。
- 問題があれば、WordPress の「リビジョン」で1つ前に戻すか、手順1のバックアップを同じ方法で送り返せば元に戻ります。

### 手順6. 後片付けと計測設定
- 確認用の下書きページをゴミ箱に入れます（管理画面から）。
- GA4 の「管理 → データの表示 → カスタム定義 → カスタムディメンションを作成」で、範囲＝イベント、イベントパラメータ名 `seat_type` `quiz_with` `quiz_priority` `quiz_area` `quiz_source` の5件を登録します（登録前のデータは後から見られません）。必要なら「管理 → イベント」で `seat_quiz_cta` をキーイベントにします。
- 1週間後に「診断開始数／結果表示数／席別の予約タップ率／第2候補の閲覧率」を見て、振り分け（§2）を見直します。

## 5. 残っている低優先度の指摘（今回は見送り）

| 指摘 | 見送った理由・今後の対応 |
|---|---|
| 席カードの「アソビューで予約する」ボタン（既存2個＋追加3個）が 320px 幅の端末だけ高さ38px（375px以上は44px以上） | 既存ボタンの書き換えが必要で、新旧の見た目をそろえる方針を優先。必要なら `integrate.py` に置換を足すだけ |
| 見出し「どの席にしようか迷ったら」に HTML アンカーを付け、診断の領域名を見出しと結び付ける | SWELL の目次機能が既存 id 付き見出しをどう扱うかを本番でしか確認できないため。本番で問題なければ2か所の修正で対応可能 |
| テーマの赤ボタン（#ff0000）の文字コントラストが基準（4.5:1）に届かない | サイト全体の設定（§4 #7）。ユーザー判断事項 |
| 結果画面の注記「このページ下の『観覧席』をご覧ください」をページ内リンクにする | 既存の見出し「観覧席」にアンカーを付ける編集と同時でないと行き止まりになるため |
| 本番でしか確認できない項目: iPhone Safari 実機のタップ感、結果写真が SWELL の遅延読み込みに触られないこと、ブロックエディタでの保存警告、GA4 DebugView | 手順3・5で確認 |
