- ねらい: 都心の花火大会との差別化。昼:観光・紅葉・飲食 → 夕方:会場イベント → 夜:音楽×花火 と目的を複数にして来場動機を作る。
- 作り: **専用ページ**(トップページ①の整理後に、トップにも短い紹介ブロックを置く前提)。「秋川で過ごす一日」を**時間軸(午前→昼→午後→夕方→夜)**で見せる。写真+時間帯+場所+一言。地名(あきる野・秋川渓谷・サマーランド・武蔵五日市・秋川駅)を含む見出しにする(検索対策)。
- 素材: 観光18選のスポットから、会場(東京サマーランド第2駐車場)や秋川駅・武蔵五日市駅からのアクセスが記事に書かれているものを選ぶ。所要時間は記事のアクセス欄の範囲だけ。紅葉の見頃・営業時間の最新は委員会確認。
- ページ末尾: 「16時頃までのご来場を目安に」「チケットは事前購入(当日券なし)」を添えて `/ticket/` へのボタン、`/access/` へのリンク。
- KPI: ページ閲覧数、「秋川 紅葉」「サマーランド 花火」等の検索表示回数とクリック率、滞在時間。
- 委員会に用意してもらうもの: 観光スポット候補の追加(渓谷・紅葉・飲食店)、所要時間の目安、写真。

### b3 = ③ 飲食・ステージのアピール(食べる／見る／楽しむ／感動する)(公開目標 10/3、10/8 第3回配信)
- ねらい: 「花火の直前に行くイベント」から「昼から楽しむイベント」へ認識を変える。
- 作り: 4つの体験(**食べる**=秋川最強肉まつり・キッチンカー約30店 ／ **見る**=ダンス・ステージ ／ **楽しむ**=秋川の自然・紅葉・子ども向け体験 ／ **感動する**=音楽×花火)を**カード形式**で並べたセクション。出店者確定後に写真・店名を更新できる構造(店舗一覧の差し込み位置を明示)。
- 置き場所: 2通りを用意する — (A) トップページ「今年の見どころ」用の**単体セクション**(`section.html` として保存: wp:loos/full-wide 1つに収める) と (B) それを含む**専用ページ** `content.html`(見出し「第8回の楽しみ方」+ 4カード + タイムテーブルの仮枠(④の確定待ち=プレースホルダー) + `/event/` `/food-application/` `/ticket/` への案内)。
- 「昨年(第7回)の例」として写真・店名を使うときはその旨を明記。
- KPI: 該当箇所の閲覧数、出店者募集ページとの回遊。
- 委員会に用意してもらうもの: 出店者・ステージ出演者の確定リスト、昨年の飲食・ステージ写真、第8回の花火演出の見どころ。

### b5 = ⑤ SNS・メディア出演情報のまとめ「秋川流域花火大会をもっと知る」(公開目標 10/10、10/22 第4回配信)
- ねらい: 購入前に雰囲気を知れる場所を作り、点在する情報(Instagram・メディア掲載・動画・過去の様子)を一箇所に集める。
- 作り: 専用ページ。構成案: このページで分かること → 動画で見る(第7回ドキュメント) → 写真で見る(`/2024-hanabi/` の写真を数枚+リンク) → Instagram(フォロー案内+フィード) → メディアで紹介されました(TBS Nスタ・ウォーカープラス・ラジオ・Yahoo!ニュース、掲載メディアロゴ) → チケットへの案内。
- 既存の `/pr/`(メディア掲載)との関係を SPEC で整理(統合するか、`/pr/` は残して相互リンクか → 推奨を書く)。
- KPI: ページ閲覧数、SNSへのクリック数。
- 委員会に用意してもらうもの: 掲載する Instagram 投稿の選定、メディア掲載一覧(媒体名・日付・リンク)、X/YouTube/LINE 公式アカウントの有無。

### b8 = ⑧ 「初めて来る人へ」ページ(行く前／会場内／帰り)(公開目標 10/17、10/22 第4回配信「購入前確認」からリンク)
- ねらい: 交通アクセス・よくある質問に分散した情報を来場の時系列でまとめ、不安をなくす。お問い合わせ件数の減少。
- 作り: 専用ページ。**行く前**(チケットは事前購入・当日券なし／到着推奨16時頃まで／服装・持ち物・持込禁止物／駐車場は事前購入・2か所／秋川駅からの行き方・電車／バス／車の比較表) → **会場内**(入場・手荷物検査／席の種類と決まり方／トイレ・授乳室・喫煙所・ごみ／飲食は会場内で／再入場可／ステージ・飲食の時間) → **帰り**(帰りのバス・シャトル=未確定のプレースホルダー／混雑・周辺住民への配慮／忘れ物の問い合わせ先=info@…)。各段階の先頭に「これだけは」3点の要約。
- 会場マップ(座席・トイレ・飲食・ステージ・救護所の位置)は**未提供→プレースホルダー**。既存の駐車場案内図2枚は使用可。
- SWELL の `loos/step` を時系列に使うと分かりやすい(参考ファイルに実例)。
- KPI: ページ閲覧数、よくある質問・交通アクセスとの回遊、お問い合わせ件数の減少。
- 委員会に用意してもらうもの: 会場マップ最新版、トイレ・救護所・飲食ブースの位置、帰りのバス時刻(交通事業者へ確認)、到着推奨時刻の再確認。

### b10 = ⑩ 天候・開催情報(開催・中止の判断、雨天対応、服装・防寒、当日の天気)(公開目標 10/24、10/31 第5回配信、11/13〜14 当日運用)
- ねらい: 当日の判断と準備の情報を一箇所で示し、電話でのお問い合わせを減らす。
- 作り: (A) 専用ページ `content.html`: 「開催状況」欄(通常時の文言「予定どおり開催します」＋更新日時の書き方。判断ルールは未定→プレースホルダー)→ 雨天時の対応(雨天決行・雨合羽)→ 中止・延期のとき(払い戻しの決まり=よくある質問の事実のみ、手続きは未定→プレースホルダー)→ 服装・防寒の目安(16℃/6℃)→ 当日の天気の見方(天気予報サイトへのリンクは**書かない**、「あきる野市の天気予報をご確認ください」に留める)→ 問い合わせ先。(B) トップページ最上部の「開催情報の帯」: SWELL の「お知らせバー」機能(カスタマイザー)で出す前提の**文言案と設定手順**を SPEC に書き、あわせて代替として wp:html の帯(通常時は非表示=`hidden`属性)も `banner.html` に用意。(C) 当日の更新手順書(誰が・いつ・どこを書き換えるか。委員会の担当者は未定)を SPEC の章として書く。
- KPI: 当日週のトップページ閲覧数、開催情報ページ閲覧数、お問い合わせ件数。
- 委員会が決めるもの: 中止判断のタイミングと告知ルール、荒天時の払い戻し方針、当日の更新担当者。
